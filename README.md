# Team Dispatch v2.6.0

本版包含新增功能與共同作業資料模型調整，因此依版本規則更新第二碼。

## 1. 日曆排程刪除日期可重新選回

修正「我的工作 → 工作內容 → 日曆排程」：
- 移除某個工作日後
- 該日期會立刻重新出現在「新增工作日」下拉選單
- 前提仍是：工作日、非國休、非整天請假、不得超過需求日

## 2. 完成 → 改回未完成

舊版只改 status，不會重排工時。

v2.6.0 改為：
- 重啟日 = 今天
- 從今天到需求日找有效工作日
- 將完整「預估總工時」重新平均分配

例如：
- 今天 9/11 改回未完成
- 需求日 9/17
- 預估 4h
- 有效工作日 9/11、9/14、9/15、9/16、9/17

則重新平均到這 5 個工作日。

如果原需求日已過：
- UI 會要求輸入新的需求日
- 再重新分配

## 3. 共同作業改為「每人一筆獨立 Task」

舊版共同作業使用一筆 Task + 多位 participant，因此 status / urgent / due date 等欄位實際上是共用的。

v2.6.0 升級為：
- 同一共同作業群組有共同的 `collaborationGroupId`
- 每一位共同作業者都有自己的 Task row
- 每人自己的 Allocation / 狀態 / 工時 / 需求日 / 緊急 / 公開屬性 / 完成 / 中止完全獨立

只有：
- 工作標題
- 工作內容

會在同一 collaborationGroupId 內同步更新。

### 中止
A 中止：
- 只中止 A 的 Task
- B / C 不受影響

### 重新啟動
A 重新啟動：
- 只重啟 A
- 刪除 A 舊的 Allocation
- 由重啟日至 A 自己的需求日重新平均完整預估工時

如果需求日已過：
- 提示輸入新的需求日
- 同時確認新的預估總工時

## 4. 舊共同作業資料升級

本版新增 `collaborationGroupId`。

執行：
`Team Dispatch → 初始化 / 修復資料表`

時會自動把舊的：
`一筆 Task + collaboratorIds`

轉為：
`每位共同作業者一筆 Task`

原本每個人的 TaskAllocations 會一起搬到新的個別 Task，不會重新平均或遺失既有日排程。

## 5. 版本顯示

新增：
- 登入頁底部：v2.6.0
- 登入後左側欄底部：v2.6.0

## 6. 週期工作重新設計

舊版只是一個「開始日～需求日」的單一期間，不是真正 recurrence。

v2.6.0 改成：
- 根據第一個「需求日」定位第一期
- 第一期間 = 該需求日所在週的星期一 ～ 需求日
- 可選「每週一次」或「雙週一次」
- 可用「週期次數」或「週期結束日」控制系列長度
- 每一期都是獨立 Task
- 每一期都重新把完整預估總工時平均在該期有效工作日
- 不會從建立日開始分配

### 範例
9/11 建立：
- 第一需求日：9/17
- 每週一次
- 4 個週期
- 每期 4h

產生：

第 1 期：9/14～9/17，共 4h
第 2 期：9/21～9/24，共 4h
第 3 期：9/28～10/1，共 4h
第 4 期：10/5～10/8，共 4h

每一期會各自排除：
- 週末
- 國定假日
- 整天請假

並在該期剩餘有效工作日重新平均。

共同作業 + 週期工作也可同時使用：
- 每一期各自建立共同作業群組
- 每位作業者每一期都負荷完整預估工時
- 各人的狀態與 Allocation 仍獨立
