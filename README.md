# Team Dispatch v1.8.0

## 1. 公開儀表板：本週同名任務合併

「本週未結任務」中，只要工作類型 / 任務名稱完全相同，就合併成一列。

例如：

```text
UAT Review / 王小明
UAT Review / 陳小華
UAT Review / 李小美
```

顯示為：

```text
UAT Review
負責人：王小明、陳小華、李小美
```

合併列：
- 本週排程：`-`
- 預估總工時：`-`
- 若需求日期不同，顯示最早～最晚日期
- 若狀態不同，狀態顯示「多筆」
- 任一子任務為緊急，合併列顯示緊急

只影響「本週未結任務」。
「未來 15 天任務」仍維持逐筆顯示並依剩餘工作量排序。

## 2. 新增任務：任務名稱可選既有值

「新增自己的工作」與「請別人協助」的工作類型欄位現在是：

`自由輸入 + datalist 下拉建議`

來源：
- 公開任務名稱
- 自己曾建立或被指派的私人任務名稱

因此不會因下拉選單把別人的私人任務名稱洩漏給不相關使用者。

仍可輸入全新的名稱。

## 3. 已存任務可修改預估總工時

點進任務詳細內容：

```text
預估總工時
[ 12.00 ] 小時 [更新總工時]
```

負責人或建立者可以修改。

### 如果從未調整日排程
已接單任務會依目前排程比例縮放；初始排程本來就是平均，所以效果相當於平均調整。

### 如果已拖拉 / 合併 / 分拆
系統不會重新平均。

例如目前：

```text
9/3  2h
9/4  6h
總計 8h
比例 25% / 75%
```

把總工時改為：

`12h`

結果：

```text
9/3  3h
9/4  9h
```

仍維持：

`25% / 75%`

包含同一天保留多個區塊的情況，也會依各區塊目前比例縮放。

待接受任務尚無 TaskAllocations，只修改 plannedHours；接單時再依正常規則建立排程。

此功能不改變：
- visibility
- Due Date
- 狀態
- 請假 / 國定假日規則

## 4. 頁面切換效率

本版減少不必要的 Google Apps Script 呼叫：

- `系統管理` 不再每次切頁重新呼叫 `adminListUsers`
- 管理員完整帳號資料隨登入後的 `loadAll` 一次載入
- 團隊出勤 14 天資料增加前端 cache
- 在同一日期區間來回切換，不再重複讀 Google Sheet
- 任一 commit 後自動清掉團隊出勤 cache，確保資料不會過期
- 任務名稱 datalist 也由既有 loadAll 資料直接產生

## 建議驗證
1. 建兩筆同名公開任務，負責人不同。
2. 免登入儀表板：本週應合成一列，負責人放在一起，兩個工時欄位為 `-`。
3. 新增工作：工作類型輸入框應可下拉看到既有名稱。
4. 把 8h 任務排成 2h / 6h。
5. 修改總工時為 12h。
6. 日曆應變成 3h / 9h。
7. 在「團隊出勤 → 我的工作 → 團隊出勤」來回切換，同一日期區間第二次應直接用 cache，切頁速度明顯改善。
