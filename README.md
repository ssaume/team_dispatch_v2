# Team Dispatch v2.5.4

本版為既有功能修改，因此依版本規則只更新第三碼。

## 我的工作 → 工作內容 → 日曆排程

原本：
- 移動日期
- 比例分拆

改為直接編輯每個工作日需要投入的工時。

例如：

9/14 [ 2.00 ] h
9/15 [ 3.00 ] h
9/16 [ 3.00 ] h

User 可直接輸入每一天的工時。

### 新增工作日

下方新增：
- 工作日下拉選單
- 「新增工作日」按鈕

下拉選單只會列出：
- 任務開始日之後
- 需求日以前（含需求日）
- 週一至週五
- 非國定假日
- 非整天請假
- 尚未存在於目前排程的日期

因此新工作日不能超過需求日。

部分請假日期仍可選，但會在選單顯示：
`請假後可用 Xh`

後端也會驗證：若該日有部分請假，這一筆任務在當日設定的工時不可超過剩餘可用工時。

Loading 仍只作顯示，其他任務的 Loading 不會占用這筆任務的可用容量。

### 移除工作日

每一列提供「移除」。

儲存前至少要保留一個工作日。

### 工時合計

每日工時合計必須等於任務的「預估總工時」。

例如預估總工時 8h：

2h + 3h + 3h = 8h → 可以儲存
2h + 3h + 2h = 7h → 不允許儲存

這可避免 Task.plannedHours 與 TaskAllocations 總和不一致。

## 更新總工時確認

現有邏輯確認為「依目前排程比例重新配比」。

例如目前：

9/14 = 2h
9/15 = 6h
總工時 = 8h

比例為：
25% / 75%

總工時改成 12h 後：

9/14 = 3h
9/15 = 9h

共同作業亦相同：
每位共同作業者會按照「自己目前的日排程比例」獨立重新配比到新的總工時。

## 相容逾期排程

如果既有排程是因請假自動後移而落在需求日之後：
- 該既有日期仍可修改工時
- 但不能透過「新增工作日」再新增需求日之後的日期
